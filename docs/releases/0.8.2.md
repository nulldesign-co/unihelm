# Unihelm 0.8.2

The Mail page can now tell you whether this server is sending. **Nothing to run
after upgrading.**

## What was missing

0.8.1 made mail install itself: save a relay on the Mail page and whatever the
server needs is installed and configured. The capability was right. The page
just could not tell you it had worked.

It showed one line — *the sending program is not installed* — which answers a
question nobody asks. What you want to know is whether mail is **going out**,
and the cases that matter are the ones where the parts disagree: a relay saved
with nothing to use it, a mail system running with no relay behind it, a move
from the old setup that stopped half way.

The agent had always worked that out and sent it to the page. The page simply
dropped it.

## What the page shows now

A card at the top of Mail with a **Sending / Not sending** badge and one sentence
saying what this server does with a message today — written by the agent from the
machine as it is, not assembled by the page.

Under it: where applications hand mail over, where containers do or why they
cannot, and how many messages are waiting, when any are.

Three things get their own warning, because each means somebody needs to act:

- **A site still holding its own copy of the relay password** from the setup
  0.8.0 replaced. Any customer on that site can read it. Saving the relay again
  finishes the move.
- **Mail configuration edited by hand** since Unihelm wrote it. Unihelm will not
  overwrite it, so the settings on the page are not the ones in force.
- **Docker networks created after mail was configured.** Containers on them are
  refused rather than delayed. Saving the relay again takes them in.

There is no Install button on the card, deliberately. Saving the relay is what
installs, and a second button for the same thing is how a panel ends up asking
you for one more step.
