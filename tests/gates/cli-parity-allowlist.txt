# Operations the CLI deliberately does not expose.
#
# Format: one entry per line, `<operation> <reason>`. The reason is not
# decoration — it is the thing a reviewer reads when they ask why parity has a
# hole in it, and `tests/gates/cli-parity.sh` refuses an entry without one.
#
# Two things the gate also checks, so this file cannot rot quietly:
#
#   - an entry for an operation that is no longer registered is reported stale;
#   - an entry for an operation the CLI *does* reach is reported stale, because
#     it is claiming an exemption nothing needs.
#
# Adding a line here is a decision, not a way to make the gate pass. If the
# reason does not survive being read aloud, write the subcommand instead.

# --- the file manager (spec §11.7) -----------------------------------------
#
# These sixteen exist so a *browser* can have a filesystem. `unihelm` runs as
# root on the machine itself, where the shell it was launched from already has
# a better version of every one of them, with tab completion, pipes and a
# pager. A `unihelm files list` would be a worse `ls` that has to round-trip
# through a socket, and the tenant-uid confinement that makes the operations
# safe for the web process buys nothing for a caller who is already root.
#
# The one that is arguably not covered by that argument is `fs.usage`, and it
# is listed with its own reason.

fs.list       the shell that launched unihelm already has ls, with completion and a pager
fs.stat       the shell that launched unihelm already has stat
fs.read       the shell that launched unihelm already has cat
fs.write      the shell that launched unihelm already has a text editor and shell redirection
fs.mkdir      the shell that launched unihelm already has mkdir
fs.rename     the shell that launched unihelm already has mv
fs.copy       the shell that launched unihelm already has cp
fs.delete     the shell that launched unihelm already has rm
fs.chmod      the shell that launched unihelm already has chmod
fs.search     the shell that launched unihelm already has find and grep
fs.compress   the shell that launched unihelm already has tar and zip
fs.extract    the shell that launched unihelm already has tar and unzip
fs.trash.list      the recycle bin is a file-manager affordance; on the host it is a directory
fs.trash.restore   the recycle bin is a file-manager affordance; on the host it is a mv
fs.trash.purge     the recycle bin is a file-manager affordance; on the host it is an rm
fs.usage      du answers this on the host; `unihelm quota usage` is the tenant-facing number
